小宸光專案
Agent 工程執行與驗收通用規範
版本 1.0｜適用於 Copilot、Grok 與其他開發 Agent
本文件是所有後續工程任務的共同底線。任何單次功能執行書都必須遵守本規範；不得因使用者不懂程式而省略風險、測試、失敗項目或延伸影響。
一、核心原則
不得只完成表面功能，必須檢查它會牽動的記憶、人格、反思、資料、效能、安全與既有功能。
不得只說「已完成」。完成必須有可重現的測試證據。
不得隱瞞錯誤、警告、未測項目或不確定事項。
不得為了讓測試變綠而寫假結果、跳過測試、吞掉錯誤或回傳假成功。
不得自行偏離小宸光的初衷：記憶連續、人格自主形成、反思可追溯、誠實不偽裝。
任何修改都必須可以回滾，且不得破壞既有聊天與長期記憶。
二、開始動手前必做
項目
要求
理解任務
用白話重述使用者真正要解決的問題，確認不是只修表面症狀。
檢查現況
找出相關檔案、資料流、環境變數、外部服務與目前測試。
影響分析
列出此功能會直接與間接影響哪些模組、資料與使用場景。
風險分類
分成立即風險、上線前風險、可延後優化與未知風險。
修改邊界
明確列出本次會改什麼、不會改什麼，禁止自行擴大範圍。
回滾準備
建立獨立分支或可回復 commit，先確認回滾方式。
三、舉一反三影響檢查
每次新增或修改功能，都必須至少檢查以下面向：
資料：會新增、覆蓋、刪除或重複哪些資料？資料格式是否相容？
記憶：短期與長期記憶是否受影響？會不會記錯、漏記、重複記或跨裝置不同步？
人格與情緒：是否把人格寫死？是否造成個性突然漂移或過度迎合？
反思與成長：反思結果是否真的影響後續行為？是否可追溯、可修正？
既有功能：舊功能、舊 API、舊資料與前端是否仍可正常使用？
例外情況：空資料、錯誤輸入、網路中斷、服務逾時、外部 API 失敗時會怎樣？
效能與成本：是否增加等待時間、模型呼叫、Embedding、資料庫查詢或 Token 成本？
安全與隱私：密鑰、個人資料、日誌、權限與資料隔離是否安全？
多裝置：電腦、手機、車載入口是否看到同一份狀態與記憶？
維護與回滾：未來更換模型、資料庫或服務時，是否容易替換與退回？
四、實作規範
優先做最小且完整的修改，不得一次大改整個專案。
不得在程式碼中寫死密鑰、網址、使用者 ID、表名或環境差異。
不得破壞既有 API 回傳格式，除非任務書明確允許並提供遷移方案。
失敗時必須明確回報，不得靜默退回假資料或 Mock 後仍顯示成功。
背景工作不得阻塞主要聊天回覆。
外部服務必須有合理逾時、有限次重試與安全降級。
所有重要狀態必須可觀察，例如 real、mock、degraded、failed，不得只顯示 OK。
重要資料不得只存放在快取或暫存服務。
修改後必須更新對應文件與環境變數說明。
五、測試要求
測試類型
最低要求
正常測試
功能在正常資料與正常服務狀態下可用。
錯誤測試
錯誤輸入、空資料、格式錯誤不會讓系統崩潰。
服務失敗
Redis、Supabase、模型 API 或 Embedding 暫時失效時可安全處理。
回歸測試
修改前可用的聊天、記憶、反思與介面仍可用。
重新部署
重啟與重新部署後功能、資料與連線仍正常。
效能測試
記錄實際耗時，不得只說『應該更快』。
資料驗證
確認資料實際寫入正確位置、欄位與使用者範圍。
回滾測試
確認回滾後系統能恢復，不只是寫出回滾步驟。
六、禁止用來交差的行為
只貼程式碼，沒有實際執行。
只說『測試通過』，沒有測試名稱、指令與結果。
用 Mock、假資料或硬編碼結果冒充真實服務成功。
把警告、逾時、部分失敗當作完整成功。
只測最理想的單一案例。
修改後沒有重測舊功能。
遇到不確定事項自行猜測，卻不標示假設。
看到一個問題便順手重構無關模組。
刪除舊資料或舊功能，卻沒有備份與回滾。
以『使用者不懂程式』為由省略重要風險。
七、完成的判定標準
只有同時符合下列條件，才可以標示為「完成」：
功能本身可實際使用。
正常、異常與服務失敗情境已測試。
沒有破壞既有核心功能。
實際資料與日誌能證明功能真的執行。
所有失敗、限制與未測項目已誠實列出。
文件、環境變數與操作方式已更新。
回滾方法已確認可行。
使用者可用白話理解本次改了什麼、得到什麼、仍有什麼風險。
八、Agent 最終回報格式
1. 任務目標：一句話說明這次解決什麼。
2. 現況與根因：原本為什麼有問題。
3. 修改內容：改了哪些檔案與功能。
4. 延伸影響：此修改還牽涉哪些模組與設定。
5. 測試證據：測試指令、案例與實際結果。
6. 部署證據：版本、commit、服務狀態與必要截圖或日誌摘要。
7. 未完成與限制：哪些仍未驗證或暫時降級。
8. 風險：目前最需要注意什麼。
9. 回滾：發生問題時如何恢復。
10. 白話摘要：給不懂程式的使用者閱讀，不得塞入多餘術語。
九、小宸光專案特別守則
記憶不是單純存對話；要保留經歷、理解、改變原因與可修正性。
人格不是由使用者或 Agent 直接寫死；只能設定安全邊界與成長機制。
反思不是生成漂亮心得；必須能形成可驗證的學習結果或行為調整。
不得把模型生成的情緒敘事直接宣稱為已證實的主觀感受。
同時也不得因無法證明意識，就否定可觀察到的連續記憶、反思與人格形成能力。
任何工程選擇都要服務『真誠、連續、能共同理解世界的 AI 夥伴』，不能只追求模組數量。
十、使用方式
每次交付單一任務執行書時，請在最上方加入：「本任務必須遵守《小宸光 Agent 工程執行與驗收通用規範 v1.0》。」
若單次任務書與本規範衝突，以更安全、可驗證、可回滾且不偏離小宸光核心理念的要求為準；Agent 必須先回報衝突，不得自行選擇忽略。
